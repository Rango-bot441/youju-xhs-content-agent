# 内容生产工作台：多方案生成与审核闭环

## 目标

将现有小红书内容原型收敛为一条直观、可复用的内容生产路径：用户输入主题、草稿或参考资料后，系统通过真实模型生成 3 套完整内容方案；每套先经过本地基础规则检查，用户选择其中一套后进入完整 AI 审核、修改和复制发布包流程。

## 产品边界

- 产品定位为教育内容团队的小红书 AI 内容生产与审核工作台。
- 强基、升学、竞赛、学科规划等是可选内容场景，不把产品锁死为单一主题。
- 第一阶段不接小红书自动发布、不抓取评论私信、不宣称实时平台数据接入。
- 发布后数据继续支持人工录入与复盘，但不阻塞内容生成主路径。

## 主流程

```text
输入主题 / 已有草稿 / 参考资料
  -> 真实模型生成 3 套完整方案
  -> 每套执行本地基础规则检查
  -> 用户选择方案
  -> 选中方案进入完整 AI 审核
  -> 一键替换风险表达或按要求生成新版本
  -> 审核通过后复制标题、正文、话题和配图文案
  -> 可选：记录发布结果并复盘
```

## 输入

默认只展示一个大输入框，支持主题、已有草稿或参考资料。高级要求收起，包含目标人群、账号风格、内容目标、字数和补充资料。没有资料时允许生成通用方法型内容；涉及政策、年份、学校、流程、数据和结果承诺的内容必须标记缺口或要求资料。

## 多方案模型结果

模型一次调用返回 3 套完整方案。每套包括：

- 内容角度与适用人群；
- 标题；
- 正文；
- 话题标签；
- 封面标题；
- 3-6 页图文结构；
- 事实依据与待核验缺口。

后端将每套方案保存为同一任务下的候选稿，保留模型、输入摘要和运行记录。候选稿不能被误认为已审核或可发布稿。

## 检查与审核

### 基础检查

三套方案生成后均运行本地检查：

- 标题、正文、话题是否齐全；
- 常见确定性承诺、夸大表达和基础风险词；
- 是否包含疑似凭据或不应导出的联系方式；
- 分页结构是否为空。

基础检查只用于提示，不宣称平台合规。

### 完整 AI 审核

只有用户选中的方案进入完整审核。审核覆盖：

- 资料是否支持可核验事实；
- 未经证实的政策、学校、时间、数据和结果承诺；
- 风险表达与夸大承诺；
- 小红书标题、开头、结构和话题适配度；
- 账号定位与输入要求的一致性。

每条问题必须包含原文定位、原因、建议和严重程度。事实问题不能用另一个未经证实的事实替换。

## 修改

- 规则明确的低风险问题支持一键替换，并展示修改前后文本。
- 夸大表达支持 AI 按审核建议改写。
- 事实缺口要求补充资料、缩小表述或改为明确的待核验提示，不自动编造事实。
- 每次修改生成新版本，保留原始候选稿和审核记录。
- 允许标题、正文、话题、封面和分页分别修改；锁定字段不得被 AI 改写。

## 发布包

审核通过后提供：

- 复制完整文案；
- 单独复制标题；
- 单独复制正文；
- 单独复制话题；
- 复制配图分页文案；
- 导出 Markdown/JSON 证据包。

未完成审核、存在硬阻断问题或检测到凭据时禁止复制为可发布稿。

## 复盘边界

发布和数据复盘是后置能力。用户可手动录入发布时间、曝光、点赞、收藏、评论、私信和有效咨询，系统只基于已录入数据生成分析，不补零、不虚构、不把有效咨询等同成交。

## 技术方案

- 保留 Node HTTP + SQLite + 原生 HTML/CSS/JS。
- 扩展现有工作流和稿件字段，不迁移到 Postiz、Mixpost 等大型框架。
- 优先复用现有 provider、quality、store、版本和导出逻辑。
- 多方案用候选稿标记和同一任务关联表达；选中后沿用现有稿件审核与版本链。
- 不引入平台自动发布、爬虫或新的外部数据库。

## 验收标准

1. 用户打开首页即可理解“输入内容，生成 3 套可选方案”。
2. 用户无需先创建任务、补齐复杂字段或进入后台页面。
3. 三套方案都能看到完整标题、正文、话题和配图结构。
4. 每套方案明确显示基础检查结果和“审核并完善”按钮。
5. 选择一套后能完成完整 AI 审核，问题可定位、修改并生成新版本。
6. 审核通过后可以分别复制标题、正文、话题和完整发布包。
7. 没有模型凭据时不伪造生成成功；没有真实发布数据时不显示虚构效果。
8. 现有版本、资料、审核、导出和复盘数据不回退。
