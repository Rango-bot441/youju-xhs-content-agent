# 有据 · 小红书内容审核工作台

面向内容运营的**本地内容审核工作台**：把任务要求、资料依据和外部稿件放进同一条可追踪流程，AI 负责整理与核验，人负责最终判断和交付。核心不是"多生成一点"，而是让每一份稿件**有依据、可追溯、不编造**。

> 状态：本地原型，持续迭代中。代码和自动化测试覆盖了主流程的各个环节；真实模型下的运行记录见作品集案例页，见文末"已知边界"。

## 主流程

```
任务要求（目标、受众、交付要求）
        ↓
资料与稿件（选择允许使用的资料，导入外部稿件）
        ↓
AI 核验（事实、风险表达、与要求的匹配度，定位问题与来源）
        ↓
人工处理与导出（修改、采纳或退回，保留版本与意见，复制 / 导出交付）
```

主入口是"导入一份外稿"；创建任务只填写需求卡（目标、受众、资料范围），本身不调用模型。

## 模块

| 模块 | 作用 |
|---|---|
| `lib/workflow.mjs` | 生成、审核、修改的流程编排；校验模型输出；导出 |
| `lib/quality.mjs` | 本地确定性检查；把审核意见定位到原文位置；对比两版稿件 |
| `lib/sources.mjs` | 资料导入、分块与检索；抓取公开网页时拦截内网和非 http(s) 地址 |
| `lib/store.mjs` | SQLite 存储：任务、资料、稿件版本、审核、运行记录 |
| `lib/provider.mjs` | 模型连接层：真实请求、超时与失败信息 |
| `lib/lead-classifier.mjs` | 评论/私信线索分类，带人工复核字段 |
| `lib/publication-import.mjs` | 发布记录 CSV 导入：预览、去重指纹 |
| `public/` | 原生 HTML / CSS / JavaScript 前端，含确定性图文模板排版 |

图文分页使用模板排版，**没有接入图像生成模型**。

## 设计要点

下列行为均有对应自动化测试：

- **不编造事实**：缺资料时保留具体问题，不伪造选题和出处；审核不能把"编造的出处"或"原稿中不存在的句子"当作依据。
- **旧结论不沿用**：修改后必须复查新版本；重新审核开始时立即撤销当前的"已通过"状态；审核期间内容变化，结果不能批准变化后的内容。
- **定向修改**：选区改稿只替换唯一选区；锁定字段由程序保证逐字不变，而不是靠提示词约束。
- **导出安全**：默认导出不带资料全文、审核记录和内部版本；证据版需显式选择；手机号、邮箱、疑似密钥会被脱敏或拦截。
- **运行可恢复**：运行可取消并释放锁；失败保留已生成的草稿并标注"尚未审核"；重试不重复生成版本；运行记录中的输入与工具结果脱敏。

## 运行

要求 Node.js ≥ 24.5，运行时依赖只有 `linkedom`。

```sh
npm install
npm start            # 默认 http://127.0.0.1:4318
npm run status       # 查看后台服务状态
npm run stop
npm test
```

可通过环境变量调整：`PORT`、`HOST`、`XHS_DB_PATH`、`PUBLIC_ORIGIN`、`ALLOWED_HOSTS`、`XHS_SOURCE_PROXY`。模型凭据只在服务端读取，不写入仓库。

数据保存在本地 `.local/`（已在 `.gitignore` 中）。

## 已知边界

- 真实模型下"导入稿件 → AI 核验 → 人工处理 → 导出"的完整闭环以本地保存的真实运行记录为准（见作品集案例页），不虚构演示数据。
- 不自动发布，不抓取平台后台数据，不保证平台审核通过。AI 核验通过不等于人工已核实事实。
- 访问控制只有域名白名单（`ALLOWED_HOSTS`）和跨站请求拦截，没有登录和用户权限。按个人本地使用设计，不要直接暴露到公网。
